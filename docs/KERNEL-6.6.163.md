# Linux 6.6.163 source, patch and ABI evidence

This is source and configuration evidence for the Issue #54 candidate, not a
release notice. It does not replace the previous release's security evidence.
Actual native AMD64 and ARM64 packages, matching signed modules, installed boot
and basic networking must pass on the exact PR head before acceptance.

## Authenticated inputs and the Stream comparison

The compiled tree comes from the separately authenticated
[kernel.org 6.6.163 stable release](https://lkml.iu.edu/2611.2/22483.html), SHA-256
`08ca57ee614714958ffc6aa6451e34fb96fc398001e7e16ff7fc6dbfccb94688`.
The signed Stream 2026.03 input remains the source for the build recipes, configs
and component inputs, not for the bytes of the kernel tree. The Stream archive
digest checked in the baseline audit was
`e9f5b20261b166b72c60b591d00b173673fe704c5f6aaf90404db457c2804910`;
its Minisign signature and trusted comment were verified against the existing
pin. For the old comparison, the kernel.org 6.6.128 TAR signature was verified
against fingerprint `647F28654894E3BD457199BE38DBBDC86092693E`; the compressed
source digest was
`669633bb8480021f15c38883fb2f6fe2087cc8b69a582f26f6b7d4ae6b348e48`.

The baseline audit replayed the four authenticated Stream patches with zero fuzz
on pristine upstream 6.6.128 and compared the resulting full paths and file
hashes against the original nested Stream kernel tar, not just its corresponding
source export. All 81,674 regular upstream-plus-patch paths and 63 symlinks are
present. All regular paths except `certs/default_x509.genkey` matched byte for
byte and all 63 symlinks matched type and target. The template difference is the
Common Name only: “VyOS Networks build time autogenerated Kernel key” versus
the upstream “Build time autogenerated kernel key”. This candidate intentionally
keeps the neutral upstream subject, while preserving mandatory signing and
fresh key generation for each architecture. The 48,043 extra archived regular
files and 20 extra links were accounted for as generated source-tree, tool,
config, build/cache and Debian package staging material. They are not inputs to
the new clean kernel tree. All 13 original recipe files (4 patches, 2 architecture
defconfigs and 7 fragments) matched both native-build inventories from
[v2026.03.14](https://github.com/michibiki-io/shirube-os/releases/tag/v2026.03.14).

## Active patch series and retained fixes

The historical patches in the root of
[`patches/kernel`](../patches/kernel) and their upstream originals remain
unchanged as 6.6.128 evidence; the build uses only the versioned
[`linux-6.6.163`](../patches/kernel/linux-6.6.163) series.
Every Stream patch must match its exact retained recipe hash. Build receipts
record the Stream inputs (`recipe-checksums.txt`), active local patches
(`kernel-tool-patches.sha256`) and effective source state
(`kernel-patch-state.txt`). Zero-fuzz application to a fresh tree does not create
backups for moved lines. Unknown patches, changed hashes, ambiguous application
and partial or changed effective source fail before packaging.

| Stream 0001 link-state device attributes | Original applies with zero fuzz. |
| Stream 0002 stackable filesystem inotify | Original applies with zero fuzz. |
| Stream 0003 perf packaging | Original applies with zero fuzz to both `scripts/package/builddeb` and `scripts/package/mkdebian`. The build repackages the actual native perf binary with dependencies from `dpkg-shlibdeps`, not the recipe's short initial dependency list or an archived binary. |
| Stream DNAT connection tracking | The exact recipe is recognized by hash. Acquire use sites are BPF socket assignment, IPv4/IPv6 established lookups and timewait purge; release sites are all three request migration sites (after timer initialization where applicable), timewait publication, SYN cookies and TFO. The local perf compatibility patch applies [Dmitry Safonov's submitted
fix](https://lore.kernel.org/lkml/20261126-perf-string-h-v1-1-8f5c39ff30f0@arista.com/)
to the exact 6.6.163 context. It changes only the `jitdump.c` include so perf
sees its own `strlcpy()` declaration on Bookworm. A local compile of that file
against Bookworm headers failed before the change and passed after it; this is
not evidence that the full native perf packages built.

After all Stream and Shirube changes, the production recipe verifies the reviewed
full-file hashes of the affected source files. The replay was tested against the
exact signed TAR to check coverage after application, not just against a commit
title, a version string or an old patch filename.

## Effective configuration comparison

The retained aggregate configs were resolved with `make vyos_defconfig` after
the production patch series. Both resolved `make kernelrelease` values were
`6.6.163-vyos`. This diagnostic used Ubuntu 24.04 GCC 13.3.0 and binutils 2.42
(native x86_64 compiler and AArch64-target cross compiler). The older exact
native configs used Debian GCC 12.2, binutils 2.40 and pahole 1.24; pahole
was not present for the configuration-only replay.

| Target | v2026.03.14 native `kernel.config` SHA-256 | 6.6.163 diagnostic `.config` SHA-256 |
| --- | --- | --- |
| AMD64 | `0c177e1e3ccedd88447c999b27855ed95c047b8c0bc50682e5220f560dc327a8` | `058b374f3a3306fa18b104a9f4932d3b6296deec95a021ff3449b269d643727f` |
| ARM64 | `8f5c434952442b14ec487327c41cca1476e36199f95971718e89b2520092e3e4` | `9a6aa44306dfe6355758ebdec103aa2a467ed1e253f00df085d600d22c5534ae` |

- Both configurations retain mandatory module signing, SHA-512, the per-build
  key path, symbol-version checking, and an empty extra trust list. IPv4, IPv6,
  VLAN, NAT and WireGuard selections are unchanged.
- The removed NTFS and SATA_INIC162X requests were off in both old configs.
  Removed ARM64 CRYPTO_DEV_SUN8I_CE_PRNG and FSL_DPAA2_SWITCH requests were off.
  NVMEM_LAYOUTS now gates layout entries. It is off on AMD64 and on on ARM64;
  the ONIE and SL28 drivers stay disabled in either case. No enabled requested
  functional feature disappeared.
- The remaining removed/changed requests are detected toolchain capabilities or
  version fields: GCC ASM GOTO workaround, AArch64 link/static-link probes (no
  cross userspace development libraries), and GCC, assembler, linker and
  pahole version fields. New default-only entries are TCP_AO off and TCP_SIGPOOL
  on for both, plus enabled ARM64 errata 3821522/4118414, the AMU counter
  workaround, and build-time mcount sort capability. Config fragments were not
  rewritten to hide those differences.

## ABI checks and remaining validation

Builds check the native package-control identities of the kernel image, headers,
perf and libc headers. Module compilation consumes the exact headers and expected
`include/config/kernel.release`. External modules are checked for their ABI
vermagic before signing and their signatures verified against the certificate
also verified against the matching kernel image. The Stream image builder's
kernel selector is changed in the effective copy only; the package manifest,
depmod hook and live GRUB kernel/initramfs paths must agree.

These checks do not demonstrate a native build or installation. Both native
staged `kernel.config` files still need comparison with the respective 6.6.128
baseline. Record package, perf dependency, signed module, boot and networking
results on each architecture against the exact candidate commit. Record ordinary
IPv4/IPv6, VLAN, NAT and VPN topology and results where run; do not treat source
replay or the other architecture as runtime evidence.
